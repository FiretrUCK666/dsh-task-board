# dsh-task-board — DSH Web GUI 任务看板插件

一个完全独立、可热插拔的 DeepSeek Harness (DSH) 客户端 GUI 插件：在侧边栏「新会话」下方增加
**任务看板**入口，点击后中间列整体切换为多列看板视图；任务以 DSH 自身的会话机制
**真实执行**（`session.prompt`），执行状态实时回写卡片。

- 不修改 DSH 源码：以 cordis 插件 + 浏览器 DOM 扩展挂载（外挂形态）。
- 卸载即恢复原状，不影响其它配置段。
- 任务数据本地持久化，刷新页面、重启 DSH 均不丢失。
- 完全独立，不依赖任何其它插件包。

## 功能

### 看板与卡片

- **侧边栏入口**：新会话按钮下方一行「任务看板」，点击即切换到看板视图；入口**实时镜像原生「新会话」按钮的表面样式**（深浅色与玻璃皮肤下都不会变透明、与原按钮一致），折叠栏显示纯图标。
- **五列看板**：待规划 / 待办 / 进行中 / 待审核 / 已完成。卡片显示标题、描述、工作区、更新时间与执行次数；执行中显示「进行中 · 第 N 次执行」，会话在等你处理时显示「等待回应」；自动化卡片带「定时/接续」徽章，失败暂停显示「失败 · 已暂停」。卡片**悬停浮现快速执行按钮**（以最新 Prompt 立即开跑）。
- **看板头部是两行命令栏**：第一行 = 返回对话图标 + 「任务看板」标题 + 状态条（正在跑 N · 排队 M）+ **自动巡航胶囊**（透明行内开关 + 展开箭头，弹层里设并发与定时窗口）+「新建任务」；第二行 = 通栏筛选搜索胶囊。统一 28px 动作节奏，玻璃皮肤下不露丑。
- **拖拽**：卡片拖到其它列 = 移动（拖到「进行中」= 立即重新执行）；**同列内拖动 = 调整顺序，上拖/下拖/中间穿插都准（插入点精确指示条）**；执行中拖到「待审核/已完成」会被拒绝并红闪提示；拖放成功后落点列有一次确认闪烁。自动化**不再把卡片绑死**——接续中的卡片照常可拖，拖到「已完成」= 停链、拖到「待规划/待审核」= 暂停、拖到「待办」= 停止接续手动接管。侧边栏的**单个会话或整个工作区文件夹也可以直接拖进来建卡**（目标列呼吸高亮），拖到哪列就落在哪列；**拖进已打开卡片的「会话」区 = 绑定（或换绑）到当前任务**（落点呼吸环 + 落位闪烁）。
- **新建任务**：默认落在**「待规划」**（初始状态可选「待规划 / 待办」），可完整配置运行配置（工作区 / Agent / 模型 / 思考程度 / 权限）。
- 所有悬浮界面（新建任务 / 卡片详情 / 评论页 / 会话面板 / 确认框）**都在看板区域内居中**，不会因侧栏或皮肤效果偏右、压到列线。

### 执行

- **真实执行**：点「执行」→ 任务由真实 agent 会话运行，状态实时回写卡片；执行会话会出现在原生会话列表，可点进去看完整对话。**执行 Prompt 以 `/` 开头时按原生命令执行**（如 `/plan 帮我实现X` 会真实进入 plan 模式：先产出计划、审批后继续执行，与原生对话输入完全一致），未匹配的命令回退为普通文本。
- **权限**：新建任务可选权限预设（选项跟随部署动态更新，不写死），执行时以原生命令应用到执行会话；未选则跟随会话默认。
- **状态回写**：刷新页面或重启后，遗留的执行任务按会话现状自动对账，不会卡在假状态。

### 复盘与干预

- **统一「会话」模型**：执行记录（板内执行的会话）与链接会话（拖入绑定的外部会话）合并为一个**按 sessionId 去重的「会话」列表**——同一会话绝不会出现两次，从执行页或链接面板进入同一会话看到的是**同一条评论线程**（评论按会话统一，结构性解决"评论区不同步"）。每个会话行统一文法：会话标题/工作区标签 + 实时状态 chip + 安静「第 N 次」注记（执行行）+ 评论摘要 + 等待状态；可隐藏（按会话，不删除、编号不变），隐藏后出现**「已隐藏 N 个会话」托盘**——每条可单独恢复，也可一键全部恢复；**解绑**在卡片详情底部（会话面板不再放三连按钮）。没有执行记录的任务也能直接在链接会话面板用「驱动任务」留言开跑；任务已完成时两模式都拒发并提示先移回待办。**拖入即瞬间同步**：把一个**正在运作（思考中）**的会话/工作区拖进看板的那一刻，卡片立即进入「进行中」、评论区出现带「原生会话」标记的那条记录、未读/呼吸环亮起，跑完自动落「待审核」——外部会话当前状态零延迟纳入并全量同步（光效、动效、评论一个不漏）。
- **评论驱动**：点某条会话行打开对应面板——左侧是该会话的实时对话（尾部，**Markdown 预览**，不显示 `#` 等原始符号）、右侧是上下文用量条 + 会话配置 + 评论区 + 固定发送区。**留言会驱动任务继续跑**（按提交顺序排队注入，显示真实位次；`/` 开头的斜杠命令走原生命令注册表，与原生对话完全一致——会开启真实回合的命令如 `/plan 消息` 会持续观察至回合真正结束、任务保持「进行中」直到完成，纯配置命令如 `/permission`、`/goal`、`/plan off` 则观察后立即生效，未知命令回退为普通文本）；模型 / 思考程度 / 权限可在此即时调整。链接面板另有「直发会话」模式 = 直接向该原生会话发消息（等于在原生对话里打字，**不会**驱动本任务）；直发消息同样**落进该会话的评论线程**（带「直发」标记），与驱动评论同线程可见。**两端状态全同步**：如果你直接在原生会话界面（不走看板）对话，任务卡片会自动进入「进行中」、跑完落「待审核」，评论区出现带「原生会话」标记的那次发言记录，需求完善会话的原生发言也会让「完善中」同步点亮——看板把原生侧活动对账进自己的状态机。
- **小功能**：详情页可**「复制为模板」**（以当前内容新建一张待规划卡，执行记录/链接不复制，**自动化规则原样带上**：次数归零、下次运行按新卡重算）；执行 Prompt 旁有**「复制」**按钮一键取用。未发送/未保存的输入会**自动记住草稿**（评论、执行 Prompt 编辑、新建任务表单、需求完善回答）——切走再回来文字仍在，发送/保存后自动清除。
- **自动化（任务级，独立分区）**：详情页以一行状态摘要折叠呈现（未启用 / 运行中·下次或第 N 次 / 已暂停·原因），展开才是编辑器（触发方式分段 + 定时或接续配置 + 按状态显隐的「跳过本次/停止接续」），无保存/取消（即改即生效）；与「自动巡航」的关系一句话讲清（本任务自动化只管本任务；巡航在板级批量调度全部任务，互不覆盖）。**开启即生效**——定时到点自动触发、接续立即开始第一轮，无需先手动执行；**按过启用后下次打开自动展开**；任务移到「已完成」即自动停用，移到「待审核/待规划」时暂停（失败标「失败·已暂停」）；无限接续启用前有一次确认。
- **自动巡航（板级）**：看板头一键开启（透明行内开关），批量执行全部待办任务；并发上限是全局的——手动、定时、接续、评论留言都走同一个调度器，满额自动排队、释放即补位。展开胶囊弹层可设**定时窗口**：**开始与结束都可单独填或一起填**——都填 = 区间内开、区间外关；只填开始 = 到点开、之后保持开；只填结束 = 立即视为开、到点关；**结束早于开始 = 自动跨到次日**（22:00 → 次日 02:00，行内显示「次日」）。时间可直接打字输入、也可点**日历按钮选日期与时分**（原生含小时/分钟）；**打开不预填**——只留占位提示，输入多少就是多少。手动开关与窗口**任意组合都确定一致**：手动只决定当前开关、到下一次窗口边界由预约接管，且**不会产生或修改任何窗口记录**；过期窗口**自动消失**（列表只显示进行中或未来的预约）。
- **需求完善**：待规划任务就是想法池——让 AI 调研你的需求、逐条向你提问，最后产出可直接执行的 Prompt（你确认后才应用到任务）。

### 集成

- **斜杠命令补全**：执行 Prompt 输入框内输入 `/` 弹出命令菜单，与原生对话输入框完全一致，DSH 或插件注册/注销命令自动跟随；提交时整行经原生命令注册表执行（执行 Prompt 与评论区共用同一投递路径，行为逐项一致）。
- 插件会在每个 agent 的系统提示中声明自己，让 agent 知道如何与看板协作；设置卡始终可用（配置服务不可用时也会提示而非消失）。

## 关键设计

- **无官方槽位，DOM 注入**：侧边栏与中间列都没有可外挂的槽位，入口与看板视图以 DOM 方式
  注入（MutationObserver 自愈、`html[data-dsh-taskboard-active]` 显隐、对话子树保持挂载）。
- **持久化用浏览器 localStorage**：客户端插件没有可写的文件通道；localStorage 与 DSH 快照
  同源。执行走客户端 runtime：`connectWorkspace()` 建会话 + `session.prompt()` 真实驱动。
- **后台结算靠会话列表对账**：未打开会话没有对话快照窗口，结算以列表为准（列表缺失→取消 /
  仍在跑→等待 / 快照可见→按错误节点 / 否则成功），幂等。
- **自动执行在浏览器端调度**：每分钟 tick、隐藏错过即跳过、进行中跳过、到点前顺延下次；
  规则生命周期（待命/生效/暂停/完成即取消）由 `ruleReadiness` 统一判定。巡航的定时窗口也由
  同一个 tick 驱动（边界翻转即生效/失效），手动开关只动当前窗口、未来窗口保留。需要标签页
  保持打开。
- **皮肤与深浅色零适配**：全板样式只消费 DSH 原生 `--dsw-*` 语义令牌（浅色/深色与皮肤插件
  重映射令牌即可整体换肤），板上经 `--dsh-tb-*` 别名引用，另见仓库 AGENTS.md「设计系统层」。
- 设置走自建路由（`/api/dsh-task-board/settings`）；权限预设实时读原生 `permissionPresets`
  （`/api/dsh-task-board/permissions`），DSH 更新预设表自动适配。

## 安装

本插件为独立插件目录，安装即把该目录作为 profile-bundle 挂到 web profile：

```sh
# 一键挂载（在 web profile 清单注册依赖 + bundle 行并 pnpm install）
node scripts/dsh-task-board.js mount

# 查看状态
node scripts/dsh-task-board.js status

# 卸载（移除注册行；重启 GUI 后恢复原状；任务数据保留在浏览器）
node scripts/dsh-task-board.js unmount
```

也可直接用官方 profile 机制（在插件目录内执行，用 `$(pwd)` 代替绝对路径）：

```sh
dsh plugin --profile web add link:$(pwd)
```

安装后**重启 `dsh web`**，侧边栏「新会话」下方出现「任务看板」入口即生效；页面刷新不够，需重启进程。

## 构建

前置：Node ≥ 20，官方 NPM SDK 可访问。类型与运行时 API 全部来自官方 NPM SDK（`@deepseek-ai/*`
devDependencies），**无需任何 DSH 源码 checkout**。

```sh
cd <插件目录>       # 例如：cd /path/to/dsh-task-board（本机位于 ~/.dsh/Plugins/dsh-task-board）
pnpm install        # 首次安装依赖
pnpm build          # 产出 lib/index.js + lib/client.js（tsdown + shared/tsdown.client.ts 预设）
pnpm typecheck      # 类型检查（node_modules 的 SDK 包类型）
pnpm test           # vitest：存储/状态流转/执行触发/cron/调度/设置路由/设置 scope
pnpm verify         # node scripts/verify-standalone.mjs . dsh-task-board（独立插件门禁）
```

## 挂载 / 卸载（profile 清单）

profile 清单中注册的行（`~/.dsh/profiles/web/package.json`）：

```json
{
  "dependencies": { "dsh-task-board": "link:<插件目录绝对路径>" },
  "dsh": { "profile": { "bundles": [ "...", "dsh-task-board" ] } }
}
```

> 注意：profile 层（bundle 行、`dsh.client` 元数据）在 dsh web 进程启动时读取，
> 挂载/卸载后需要**重启 dsh web GUI** 才生效（页面刷新不够）。

## 数据存储位置

- 任务台账存于浏览器 localStorage，键 `dsh.taskBoard.v1`（同一来源跨刷新/重启持久）。
- 自动巡航状态（开关/并发/定时窗口）独立存于键 `dsh.taskBoard.cruise.v1`。
- 卸载插件后数据保留；如需清除，浏览器控制台执行
  `localStorage.removeItem("dsh.taskBoard.v1")`（巡航为 `removeItem("dsh.taskBoard.cruise.v1")`）。
- 存储层是 `TaskStore` 接口（`src/core/store.ts`），后续可换成 IndexedDB 或
  host 文件通道而不动上层逻辑。

## 手动验证步骤

1. `pnpm build` → `node scripts/dsh-task-board.js mount` → 重启 DSH → 刷新
   Web GUI 地址（默认 `http://127.0.0.1:3080`，以实际端口为准）。
2. 侧边栏「新会话」下方出现「任务看板」入口行；点击 → 中间列切换为五列看板。检查：入口在
   **浅色 / 深色 / 玻璃皮肤**下都与「新会话」按钮外观一致且不透明（镜像机制保证）。
3. 「+ 新建任务」填标题/描述/Prompt（Prompt 输入框内输入 `/` 会弹出命令菜单，可选中
   插入命令）；「初始状态」默认选中**「待规划」**（可切换「待办」）→ 卡片出现在所选列。检查：
   新建任务弹窗**在看板区域内居中**（不贴列线、不偏右）。
   待规划任务可在详情页「需求完善」里让 AI 调研并打磨出可执行的 Prompt。
4. 点卡片 → 详情在看板内居中。执行记录与链接会话统一为**一个按 sessionId 去重的「会话」
   列表**（同一会话绝不出现两次）：执行行身份=该次会话标题 + 安静「第 N 次」注记，链接行
   = link 图标 + 标题 + 工作区胶囊，「查看会话」是紧凑小按钮；每一行的评论区都是**同一个
   会话的同一线程**。点「执行」→ 卡片变「进行中」；agent 跑完后落「待审核」，行内直接显示
   最新评论与等待状态，可「查看会话」跳转真实 transcript。「自动化」模块默认折叠为一行
   **三态摘要**（未启用 / 已暂停(原因) / 运行中），展开为完整编辑器。详情页有**「复制为模板」**
   （新建同款待规划卡，自动化规则带上、执行记录不复制）与 prompt 旁的**「复制」**按钮。点
   某个会话行 → 打开该会话面板（对话 + 上下文条 + 配置 + 评论区 + 固定发送区；巡航未开时
   留言显示「已保存」，开启后按并发预算排队注入，可取消未注入的）；执行行打开执行页、链接
   行打开链接面板。点行内「隐藏」→ 该会话从列表消失，下方出现**「已隐藏 N 个会话」托盘**，
   每条可单独「恢复」，头部可一键「恢复全部已隐藏」。
5. 点详情「编辑」修改标题/描述/Prompt（或运行配置）→ 保存后卡片立即更新；再点
   「执行」，会话以新标题命名、发送的是新 Prompt。执行 Prompt 块右上角的**复制按钮**随
   hover 浮现（点击变勾号「已复制」）。
5b. 两端同步：某任务跑完在「待审核」后，**直接去原生会话界面**（点行内「查看会话」跳到
   原生对话）再发一句话 → 回到看板，卡片自动进入「进行中」、评论区多一条带「原生会话」
   标记的记录、agent 回复后卡片落「待审核」。任务在「完善需求」时去原生完善会话发言，
   「完善中」徽章同样实时点亮。评论与对话文本以 **Markdown 预览**（标题/粗体/代码/列表/
   链接等直接渲染，不显示 `#`）。
6. 自动化（定时）：详情 →「自动化」勾选启用（**开启即生效，无需先手动执行**；此后**重新
   打开详情时该模块自动展开**），选预设「每 10 分钟」（cron `*/10 * * * *`），卡片出现「定时」
   标识；到下一个整 10 分钟点，卡片自动进入「进行中」并最终落「待审核」。详情「下次运行」
   实时显示；点「跳过本次」可把下次运行顺延到下一个匹配时刻。失败后落「待审核」并暂停
   （摘要显示「已暂停 · 失败」、卡片显示「失败 · 已暂停」），到点不复活——「重新执行」或
   移到待办即恢复。
7. 拖拽：卡片拖到其它列 → 移动，可**拖到目标列指定位置精确插入**（蓝色粗条提示落点；
   拖到「进行中」→ 立即重新执行；执行中拖到「待审核/已完成」红闪拒绝）；同列拖动 →
   调整顺序，**上拖/下拖/中间穿插都准**（精确指示条）。**接续中的
   卡片不再被绑死**：拖到「已完成」= 停链；「待规划/待审核」= 暂停；「待办」= 停止接续手动
   接管。卡片**悬停浮现 ▶ 快速执行**按钮。侧边栏会话/工作区拖进看板可建链接任务卡（显式
   拖入的单个会话即使被标记归档/空白也会显示；工作区文件夹中的会话按序展示、工作区标签稳定）。
   **打开卡片详情后，把侧边栏的会话/工作区直接拖进「会话」区** → 该任务绑定（或换绑）到新
   来源，落点呼吸环 + 落位闪烁；绑定工作区文件夹后，文件夹里**新开的会话自动出现在列表**
   （无「同步」按钮）。
8. 完成后接续：详情「自动化」→ 模式切到「完成后接续」并启用 → **立即开始第一轮**；此后
   每次完成后自动续跑，卡片持续「进行中」；设次数上限则跑满后停止并落「待审核」；留空=
   无限（启用有确认弹窗）；「停止接续」只停自动化、不动卡片列。
9. 自动巡航：看板头开启「自动巡航」（透明行内开关；并发上限先设小如 1）→ 待办任务逐个
   开始执行，完成后进入「待审核」；关掉后不再取新任务、已开始的跑完。上限是全局并发——
   手动/定时/接续/评论也走同一调度：预算满时排队、释放即补位（可开多条评论后开启巡航
   观察「排队中 · 第 N 位」逐条注入）。展开巡航胶囊弹层：设并发 + 加一个**定时窗口**
   （开始/结束），窗口开始自动开启巡航、结束自动关闭；手动「开」= 从现在一直保持（无结束
   时间），手动「关」= 只关当前窗口、保留已设的未来窗口。
10. 刷新页面/重启 DSH → 任务与巡航开关仍在；卸载插件 → GUI 恢复原状。
11. 链接会话与留言驱动：把侧边栏一个**会话**（或工作区文件夹）拖进看板 → 出现链接会话行
    （拖到哪列就建在哪列）；打开该会话面板，默认「驱动任务」——输入留言发送 → 卡片出现
    「评论排队 N」→ 开启自动巡航 → 留言注入会话并跑完落「待审核」，面板评论线程显示成功；
    排队中可随时取消。切到「直发会话」再发一句 → 消息直接进原生会话，卡片状态不动，但
    该直发消息**也会出现在本会话的评论线程**（带「直发」标记），与驱动评论互见。
12. **评论按会话统一**：在某个执行记录的评论页留一句 → 打开同一会话（若它也出现在链接会话
    分组）的面板，能看到这条评论；从链接面板「驱动任务」留的评论，也会出现在对应执行页；
    直发消息同样入线程。同一原生会话的所有评论互见同一线程，不再各看各的。
13. 玻璃皮肤/深浅色下滚一遍：入口不透明、浮层看板内居中无白块、工具栏与自动巡航透明一致、
    内表面可读、`prefers-reduced-motion` 下动效静态降级。

## 路线图（调研驱动，向「工作台」演进）

以下方向来自对 Linear / Notion / Todoist / ClickUp / Things / Obsidian 等产品的
全文调研（AnySearch + Exa），按「对本插件的性价比 + 实现成本」排序；统一守住
铁律：只复用现有组件与令牌、零第三方 UI 依赖、新数据一律轻归一化旧数据零影响、
凡是增量字段都先在对话说明并确认、尽量用纯派生函数不落维护面。

- **一期（建议优先）**：批量操作（多选卡片移动 / 加标签）、搜索增强（全文 + 标签/状态\r?\n  组合过滤）、统计面板（完成率 / 耗时 / 趋势，纯 CSS 条形图）。
- **二期（可做，低风险高价值）**：模板库与快速添加（复用 `copyTask` 与 `time-parse`）、
  「本周回顾」总结面板（纯派生、可复制为 Markdown）、任务引用与反向链接（详情页回链栏）、
  自动化增强（状态流转 + 截止提醒，扩展现有 `ScheduleRule` 条件）、日历 / 时间线视图。
- **明确不做**：完整甘特图、ClickUp 式「一切应用」扩张、复杂自然语言解析、力导向图、
  游戏化——它们违背「苹果式克制 + 长期零维护」。
